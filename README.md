# 마감한끼

가상 성수동 가게와 메뉴로 예약 흐름을 보여 주는 데모입니다. 시작 화면의 `고객으로 체험` 또는 `점주로 체험`을 누르면 아이디·비밀번호 없이 시작합니다. 고객과 점주가 같은 D1 데이터의 상품 및 주문 상태를 봅니다. 고객 화면은 `/app`입니다.

## 고객 흐름

- 상품 카드와 상세에서 판매 중이면 `예약 요청 가능`, 품절이면 `품절`, 마감이면 `마감`으로 표시합니다. 수량 선택은 없습니다.
- `골목세트`는 고객 설명과 현재 예약 가능한 상품의 ID, 이름, 카테고리, 설명을 OpenAI API에 보내 두 가게의 메뉴와 추천 이유를 받습니다. 서버는 등록된 상품 ID, 서로 다른 가게, 가게 간 예상 도보 10분 이내, 응답 대기 5분과 방문 이동 시간을 감안한 픽업 가능 여부, 서울사랑상품권 조건을 확인합니다.
- 세트 카드에는 메뉴별 할인가, 합계, 추천 이유, 픽업 마감, 방문 순서, 상품권 가능 여부가 표시됩니다. 추천 상품 ID와 이유는 D1에 저장합니다.
- 피드의 `오늘의 마감한끼`는 저장된 추천을 현재 판매 상태와 이동·픽업 가능 시간으로 다시 확인한 뒤 주변 가게의 대표 카드 한 장을 표시합니다. 저장된 추천이 없으면 새 조합을 생성하며, 가능한 조합이 없으면 섹션을 숨깁니다. 성동사랑상품권 조건을 선택하면 시연 가게 두 곳 모두 사용 가능으로 설정된 조합만 표시합니다.
- 예약 요청을 보내면 고객은 가게별 응답 상태와 대기 안내를 볼 수 있습니다. 두 가게가 모두 수락하면 픽업이 확정됩니다. 어느 한 가게가 품절 처리하거나 5분 내 모두 수락하지 않으면 종료됩니다. 결제는 요청 당시의 상품별 가격으로 각 가게에서 현장 결제합니다.
- 품절 주문에는 대체 메뉴 추천 화면이 열립니다. 가까운 다른 가게의 유사 메뉴 중 현재 예약 가능하고 픽업 시간에 맞는 상품만 표시하며, 선택하면 원래 주문과 연결된 새 예약 요청을 보냅니다. 두 가게 세트였다면 유지할 메뉴도 다시 예약 확인을 받습니다.

## 점주 흐름

- 주문 탭은 `진행 중인 주문`, `수락한 주문`, `완료` 세 블록입니다. 진행 중인 주문에 요청 당시 가격, 남은 응답 시간, 수락·품절 버튼이 나옵니다. 수락한 주문은 다른 가게 응답 대기와 픽업 확정을 구분하며, 수령 완료를 기록할 수 있습니다. 완료 블록은 수령 완료, 품절, 응답 시간 초과, 픽업 미수령을 보여 줍니다.
- 상품 등록과 수정에는 정가, 최저 판매가, 픽업 마감시간을 입력합니다. 등록 수량은 받지 않습니다. AI 초안도 수량을 추출하지 않습니다. 점주는 요청을 받을 때 재고를 확인하고 수락 또는 품절을 선택합니다.
- 마감까지 2시간 초과면 10%, 1시간 초과~2시간 이하면 20%, 1시간 이하면 35% 할인합니다. 최저 판매가보다 낮아지지 않습니다. 주문에는 요청 시점 단가가 저장됩니다.

데이터 구조와 주문 상태는 [ERD.md](ERD.md)에 정리했습니다. 가게 간 도보 시간은 좌표 간 거리로 추정하며 실제 보행 경로 API는 연결하지 않았습니다. 결제와 실제 가게 주문 전송도 연결하지 않았습니다.

## 실행

`npm install`, `npm run build`, `npm run start`로 실행합니다. `OPENAI_API_KEY`는 Sites 런타임 비밀 변수로 설정합니다. `OPENAI_MODEL`은 선택 사항이며 기본값은 `gpt-4o-mini`입니다. `node --check public/reservations.js`와 `npx tsc --noEmit`으로 코드를 확인할 수 있습니다.
